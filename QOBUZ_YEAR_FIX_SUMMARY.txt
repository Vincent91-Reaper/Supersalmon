QOBUZ YEAR EXTRACTION FIX - SUMMARY
================================================================================

USER REQUEST:
"I provided brucelee94 with this https://play.qobuz.com/album/wm81cckc1w28a 
to scrape metadata from and it keeps giving me error 'Site upload failed: 
Year of remaster/re-issue must be entered. (200)'. My guess is the year info 
is not stored in the Qobuz URL. In case like this can brucelee94 just extract 
the year info from original file's metadata?"

STATUS: ✅ FULLY IMPLEMENTED

================================================================================
WHAT WAS FIXED
================================================================================

PROBLEM:
- Qobuz scraper's parse_release_year() returns None in certain cases
- When edition exists but doesn't match keywords (Live, Remaster, etc.)
- Caused metadata["year"] to be None
- Upload failed with "Year of remaster/re-issue must be entered"

SOLUTION:
- Added fallback logic in get_metadata() after scraping
- If year is missing from scraped metadata, extract from file tags
- Three-tier fallback system ensures year is always present

================================================================================
THREE-TIER FALLBACK SYSTEM
================================================================================

TIER 1 (Primary): Extract from File Tags
- Read year field from FLAC/audio file tags
- Use most common year if multiple files have different years
- Addresses user's specific request

TIER 2 (Secondary): Extract from Date Field
- If year field is missing, parse date field
- Extract 4-digit year from date string
- Handles edge case where only date is available

TIER 3 (Tertiary): Use Current Year
- Last resort fallback if no year information found anywhere
- Logs warning so user knows
- Ensures upload never fails due to missing year
