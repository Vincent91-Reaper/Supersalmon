## What Each Method Does

### parse_release_label()
- Called during initial metadata parsing
- Gets label from API response
- Passes to parse_copyright() function
- Needed to handle dict format

### process_label()
- Called after all metadata collected
- Checks if album is self-released
- Returns final label value
- Also needed to handle dict format

## The Problem

Both methods could receive label as dict:
- Deezer API inconsistently returns label as string OR dict
- {"id": 123, "name": "Label Name"} → dict format
- "Label Name" → string format

Previous fix only handled dict in parse_release_label()
process_label() still returned dict directly, causing the error

## Complete Solution

### Fix 1 (commit 63e3fdd): parse_release_label()
```python
def parse_release_label(self, soup):
    label = soup.get("label")
    if isinstance(label, dict):
        label = label.get("name", "")
    return parse_copyright(label)
```

### Fix 2 (commit 453dbcd): process_label()
```python
def process_label(self, data):
    label = data["label"]
    
    if isinstance(label, dict):
        label = label.get("name", "")
    elif not isinstance(label, str):
        label = str(label) if label else ""
    
    # Check self-release...
    return label  # Always string!
```

## How Label Flows Through Code

1. API returns album data → label can be dict or string
2. parse_release_label() called → ✓ converts dict to string
3. process_label() called → ✓ converts dict to string
4. data["label"] used elsewhere → ✓ always string, never dict
